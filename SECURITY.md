# Security and requirements handling

Specifications can contain sensitive requirements, user data, credentials, or internal architecture. Use approved tools and providers, and do not include secrets in prompts, issues, or commits.

Before running any generated command or automation, inspect its source and side effects. Treat generated requirements and implementation plans as proposals that need human review, security checks, and testing.

Report vulnerabilities privately through GitHub reporting if enabled or contact the repository maintainer through a private channel. Do not publish credentials or exploit details publicly.
